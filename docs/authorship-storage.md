# Authorship storage in .docx (A5 spike)

> **Status:** spike done 2026-10-13 · Margin and upstream WordCraft round trips run · **Word round trip not run: Microsoft Word is not installed on this Mac** (harness ready, see §6) · Decision: ADR "A5 spike" in `docs/decisions.md`

## 1. Question

Margin keeps "this text was written by the AI (author, model), accepted at T" after a suggestion is
accepted (HANDOFF §10, V2–V4). How is that stored inside a `.docx` so that it

- survives Microsoft Word opening and saving the file, including edits around and inside the
  marked text;
- survives upstream WordCraft (`storytold/wordcraft` main) opening and saving it;
- stays invisible or at least unobtrusive to a person editing in Word;
- keeps the file valid OOXML.

Losing the marks is tolerable; a file Word or WordCraft refuses or repairs is not.

## 2. Candidates

| | Mechanism | Where the metadata lives |
|---|---|---|
| **A** | Hidden bookmarks `_MarginAI…` around the AI runs (ECMA-376 §17.13.6; a leading `_` hides a bookmark from Word's Bookmark dialog) | Custom XML data part `customXml/itemN.xml` in our own namespace `urn:margin:authorship` (§11.3.5, with `itemPropsN.xml` and relationships), one `span` per bookmark: author, kind, model, acceptedAt, length, hash |
| **B** | Nothing in the body | Same part, spans anchored by paragraph index + character offsets + hash |
| **C** | Attributes in our namespace on each AI `w:r`, namespace listed in `mc:Ignorable` and `mc:PreserveAttributes` (ECMA-376 Part 3) | On the runs |
| **D** | Inline rich-text content controls (`w:sdt`, §17.5.2) with `w15:appearance="hidden"` ([MS-DOCX]) | `w:tag` of the control |
| **E** (added) | A hidden character style `MarginAI` on the AI runs | Same part as A, spans anchored by style |

Considered, not built: comments (visible balloons); leaving the suggestions as tracked changes
(HANDOFF's "cheaper first step": that is pending, not accepted, text); editing-permission ranges
`w:permStart/End` (meant for Restrict Editing, Word may shade them); `docProps/custom.xml`
properties (flat values, shown to the user under Properties › Custom, and no anchor, i.e. B).

## 3. Test set-up

- **Document.** Four paragraphs of our own text with three AI spans: one mid-paragraph, one
  whole paragraph, one across two runs with different formatting (plain + bold). Generated by
  this repo's docx writer; what the writer has no API for (our custom XML part, the ignorable
  attributes) is patched into the package afterwards. Output is byte-identical on every run.
- **Round trips.** Margin (this branch) and upstream WordCraft (`storytold/wordcraft` main at
  `159b84f`, 2026-10-13, built from a throw-away worktree), each twice: `convert` (open + save)
  and `run … --save` with edits that hit every case the brief asks for: an insertion at the start of
  the document (shifts every offset), an insertion inside span 1 (`river` → `wide river`), a
  deletion at the start of span 2 (`Seewis `), typing right after span 3 (` AFTER`).
- **Word.** Not run. There is no Word bundle in `/Applications`, Launch Services has no
  `com.microsoft.Word`, and `osascript` cannot reach it; only a Microsoft AutoUpdate remnant is
  left. The AppleScript round trip is written (open → scripted edits through Word's object
  model → save as .docx → close; no keystrokes, no clicking) and wired into `run.sh`; it runs as
  soon as Word is installed. The Word columns below are **expectations** from the OOXML spec and
  Microsoft's published bookmark notes, not measurements.
- **Validity.** `authorship_spike check` parses every XML and `.rels` part, verifies that every
  part has a content type, that every internal relationship target exists, that bookmark ids are
  unique and no start or end is orphaned. Every file in every stage: `issues=0`.

## 4. Results

### 4.1 Survival

| Candidate | Margin + upstream, no edit | Margin + upstream, with edits | Word, no edit (expected) | Word, with edits (expected) | Visible in Word? | Complexity for Margin |
|---|---|---|---|---|---|---|
| **A** bookmarks + part | **kept**, report identical | **kept**: bookmarks shrink and grow with the text; the stored hash flags the two edited spans | kept: bookmarks are core WordprocessingML; custom XML parts are Word's own extension store and survive save | kept: text added inside or right after the opening bracket is included, text added right after the closing bracket is **not** (Microsoft, *Troubleshoot bookmarks*); deleting part of the text keeps the bookmark; copying within the document does not copy the bookmark | Hidden by default. Grey `[ ]` brackets only if the person turns on *Show bookmarks*; the names only in the Bookmark dialog with *Hidden bookmarks* ticked | **Low**: bookmarks and custom XML parts already round-trip through the model (`InlineObject::BookmarkStart/End`, `Document::passthrough`). New: write/read one part, reconcile on load |
| **B** part only (offsets) | kept | **broken**: after one insertion before them, 2 of 3 spans point at other text | kept (nothing in the body to lose) | broken by any edit before a span | Invisible | Low to write; cannot be repaired without the text itself |
| **C** ignorable attributes | **lost** on the first save, even without edits (the reader builds typed run properties and drops what it does not model; same upstream) | lost | lost, most likely: Word writes back only markup it models; honouring `mc:PreserveAttributes` for foreign namespaces is not something we can rely on | lost | Invisible | Would need reader and writer changes in the docx crate, here and upstream, and still die in Word |
| **D** content controls | **kept**, report identical | **kept**: controls track the edits; the ` AFTER` typed at the end went **inside** the control | kept: content controls are Word's own; `appearance="hidden"` draws no box or title tab | kept; typing at the end stays inside the control (that is how controls work), so a person's continuation becomes "AI" | No frame with hidden appearance, but the control is still there: right-click offers *Remove Content Control*, the Developer tab lists it, and selection behaves as "inside a control" | Low: `ContentControl` with `tag` and `extra` round-trips |
| **E** character style + part | kept | kept, but ` AFTER` typed after span 3 **inherits the style** (over-attribution), and the style carries no per-span identity, so the part cannot tell spans apart after an edit | kept | same inheritance when typing after a span; *Clear Formatting* removes it | Hidden style, still visible in the Styles pane with *All styles* and in Reveal Formatting | Low |

### 4.2 What the edits did (Margin and upstream, identical)

| Span | Accepted text | After the edits (A, bookmark) | After the edits (D, control) |
|---|---|---|---|
| 1 | `Mist lifts off the river by eight,` | `Mist lifts off the wide river by eight,` (edit inside, hash mismatch) | same |
| 2 | `Seewis sits above the Prättigau, …` | `sits above the Prättigau, …` (first word deleted, hash mismatch) | same |
| 3 | `pack a map and good boots` | `pack a map and good boots AFTER` (typed at the end went inside) | same |

Typing at the end of a span extends it in WordCraft's editor (for both A and D). That is editor
behaviour Margin controls: on accept, the AI span is a bookmark, and Margin's insert at a span's
end must go after the `BookmarkEnd` object, matching Word's documented rule. Upstream has no
reason to care.

## 5. Recommendation: A, hidden bookmarks + custom XML part

- It is the only candidate that is kept by both editors **and** keeps per-span identity **and**
  needs no change to the docx crate (here or upstream): the two pieces it uses already
  round-trip.
- Word's documented bookmark behaviour is what we want: edits inside stay AI, text typed after
  the closing bracket is the person's, partial deletes keep the mark, copies do not carry it.
- Invisible by default, no right-click affordance, no Developer-tab presence (unlike D).
- Readers other than Word and WordCraft (Pages, LibreOffice, Google Docs) keep bookmarks and
  ignore custom XML parts; the worst case is losing the marks, never a refused file.

**Risks and mitigations**

1. **Not measured in Word on this machine.** Run `scripts/authorship-spike/run.sh` on a Mac with
   Word before building A5's persistence (a one-time macOS automation prompt will appear the first
   time; refusing it fails the run with error -1743). If Word drops bookmarks in a flow we care
   about, D is the fallback.
2. **Over-attribution after a person edits inside a span.** The bookmark keeps the edited text.
   Mitigation: store the accepted text in the part (not just its hash) so Margin can diff on load
   and keep only the unchanged characters as AI (§6). Cost: the AI text is in the file twice; cap
   it (hash only above ~10,000 characters per span).
3. **Name clashes.** Pasting between two Margin documents can bring a second `_MarginAI1`. Use
   unique names (`_MarginAI_<8 hex>`), and keep the first on load.
4. **Bookmark churn.** Hundreds of small spans are fine; coalesce adjacent spans with the same
   author on accept, and drop collapsed ones on save.
5. **A person who shows bookmarks sees grey brackets.** Accepted: it is an opt-in Word setting,
   and the names say what they are.

## 6. What Margin must do on load (reconciliation)

The model, not the part, is the source of truth; the part is rewritten from the model on save.
On load, for `customXml/item*.xml` with root `mg:authorship` (`urn:margin:authorship`):

| Found | Do |
|---|---|
| Span entry, bookmark present with start and end in one story, start ≤ end | Keep. Compare the text with the stored text/hash: equal → AI as stored; different and text stored → diff (bounded, character-level), attribute only the common characters to the AI; different and hash only → keep as AI, flag `edited` |
| Span entry, bookmark missing (Word dropped it, or the text was deleted) | Drop the entry, log one line |
| Span entry, bookmark collapsed (start == end) | Drop entry and bookmark |
| Bookmark start without end, or end without start (the reader already skips ends whose id has no start) | Drop entry and bookmark |
| Bookmark end before its start, or crossing into another story / table cell | Drop entry and bookmark |
| Two bookmarks with the same name | Keep the first, drop the entry for the second, rename on save |
| `_MarginAI…` bookmark with no entry | Stale: remove on save |
| Span containing tracked changes | Characters in a tracked deletion are not counted; a person's tracked insertion inside the span is the person's |
| Overlapping or nested AI spans (accepted twice) | Merge |
| Part malformed, unrelated, or another store's root | Ignore; `keep_custom_xml` already carries foreign stores through unchanged |

On accept: wrap the accepted insertion in a new bookmark, record `{author, model, acceptedAt,
text}`; coalesce with an adjacent AI span of the same author in the same paragraph. On insert at
a span's end: place the text after the `BookmarkEnd` object.

## 7. Harness

- `crates/docx/examples/authorship_spike.rs` — `make <dir>` writes the five candidate files;
  `check <file.docx>` prints one stable line per bookmark, control, marked run, span and issue,
  ending with a `summary` line. Diff two reports to see what a round trip changed.
- `scripts/authorship-spike/run.sh` — builds, generates, round-trips through Margin, upstream
  (`UPSTREAM_CLI=…`) and Word (when installed), prints the table. Outputs in
  `plan/word/authorship-spike/<stage>/` (gitignored; Word's files are never committed).
- `scripts/authorship-spike/word-roundtrip.applescript` — Word via AppleScript only.
- `scripts/authorship-spike/word-shot.sh` + `window-ids.swift` — screenshot of Word's window(s)
  by window id if a round trip hangs (a repair dialog), never the whole desktop.
